# ADR-007: v0.3 install layout and suite

- Status: Accepted
- Date: 2026-09-14

## Context

Through 0.2.x the project grew install profiles, many domain packs, presence checks, and CLI output formats. The install script flattened every pack to `basename` under `docs/guardrails/`, so pairs such as `agents/resilience.md` and `checklists/resilience.md` (and later `cost`) overwrote each other.

Consumers also needed clearer pairing with [enterprise-github-template](https://github.com/rmkr-dev/enterprise-github-template), selective CI checks, and better install discoverability (`--dry-run`, `--list-profiles`, manifests).

## Decision

Ship **v0.3.0** as a coherent milestone that:

1. Preserves `agents/|checklists|prompts/` relative paths when installing (breaking path change vs flat 0.2.x copies).
2. Keeps the optional Python validator as presence-oriented checks with `--only` / `--skip` and JSON output.
3. Documents enterprise-github-template pairing without duplicating template process docs.
4. Treats install profiles (`baseline`, `api`, `ops`, `data`, `security`, `full`) as the primary consumer UX.

## Consequences

- Consumer `AGENTS.md` links must use nested paths after reinstall (for example `docs/guardrails/agents/core.md`).
- Existing flat installs keep working until overwritten; re-run `install-packs.sh` to migrate.
- Pack authors may reuse basenames across categories safely.
- Further 0.3.x releases may add packs/checks without another layout break.

## Alternatives considered

- Prefix filenames (`checklist-cost.md`) — rejected; harder to map back to source tree.
- Separate dest roots per category — rejected; one `docs/guardrails/` tree is simpler for consumers.
