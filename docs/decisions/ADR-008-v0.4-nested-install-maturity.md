# ADR-008: v0.4 nested-install maturity (no layout break)

- Status: Accepted
- Date: 2026-09-14

## Context

ADR-007 introduced the nested `agents/|checklists/|prompts/` install layout as the **v0.3.0** breaking change. The 0.3.x line then added profiles, pack modules, CI/docs polish, and migration aids. Consumers still needed:

1. Accurate sample/install docs (no lingering flat paths).
2. Installer help detecting flat 0.2.x leftovers (warn, do not delete).
3. Profile catalog consistency (`--list-profiles`, CLI `profiles`, bash arrays).
4. A stable CI pin on `rmkr-dev/gha-reusable-workflows` `python-ci@v0.4.0`.

Shipping another wave of domain packs without closing the migration story would dilute the milestone.

## Decision

Treat **v0.4.0** as a **maturity / coherence** release for nested install — not a second layout break:

1. Keep nested install paths; migration guide + sample `AGENTS.md` + Option B stay nested-only.
2. Keep `warn_flat_leftovers` on install and `--dry-run` (advisory only).
3. Keep profile catalogs synced via tests (`test_profiles_sync`, `test_list_profiles_sync`).
4. Prefer high-signal installer/docs/CI work over new pack modules until a later ADR.
5. CI remains pinned to `python-ci@v0.4.0` unless a new ADR changes the pin.

## Consequences

- v0.4.0 changelog should summarize nested-install maturity rather than introduce a new pack theme.
- New packs after 0.4.0 still belong under nested categories; no basename flattening.
- Governance and similar niche modules may remain `full`-only until a profile need is clear (avoid pack spam).

## Alternatives considered

- Jump to 1.0.0 — rejected; validator remains presence-oriented and optional.
- Another layout break (separate dest roots) — rejected; ADR-007 layout is sufficient.
- Bundle many new packs into 0.4.0 — rejected; conflicts with “high-signal / avoid pack spam”.
